# Concrete overlap packet binding in Lean

Scope: extend draft PR #500 with a reproducible binding of canonical Mojo
occurrence packets to `PscVerif.OverlapContraction.Certificate`. This is an
implementation of the first remaining interface obligation, not a claim that
the geometry of PR #496 or general C4/PSC is formalized. Concrete acceptance
is credited only for a completed kernel replay and matching full-packet oracle
receipt. Resource exhaustion is an incomplete replay.

## Assumptions and hypotheses

The canonical graph and weights are generated by the unchanged
`psc.c4_pair_overlap_attractor` engine for each index 0 through 17. The
Mojo exporter is `kernel/c4_overlap_lean_export.mojo`. It exports every state
and every ordered occurrence target, retaining repeated targets. There is no
spectral approximation, sampled row, or deduplication in this binding.

`OverlapPacket.lean` checks dimensions, the ordered lookup table's layout,
three distinct-letter roots, target bounds, positive weights and every inequality

$$20\sum_{e\in\operatorname{row}(i)}w_{\operatorname{target}(e)}\le102w_i.$$

The metadata state string is a coordinate label, not a formal geometric set.
The graph-to-overlap cover and the correctness of the native graph constructor
remain explicit refinement obligations. The real mass recurrence and spectral
gap are still arguments to `Packet.sound`.

## Derivation / reduction

A balanced binary table avoids the linear kernel lookup of Lean arrays. The
proved `Table.get?_eq_toList` identifies lookup with the ordered leaf list
when the cached cuts are valid; `HeaderValid` checks that layout. Rows are
packed into unbounded natural literals to reduce syntax and elaboration cost.
The low fields are: weight (20 bits), row length (10), state (25), then 14 bits
per occurrence target, first target least significant. State fields are two
2-bit letter indices and three 7-bit coordinates biased by 64. The native
exporter refuses weights outside 1..1,000,000, coordinates outside -40..40,
letters outside 0..2, length at least 1024, and targets outside 0..16383.
It never truncates an out-of-budget field. The current graphs fit these budgets;
changed graphs outside them require a reviewed codec change. A Lean canonical
payload check also rejects unused high payload beyond the declared length.

Each generated module supplies a kernel proof of the header and of consecutive
row ranges of at most 32 rows. `checkRange_append` combines adjacent ranges;
`valid_of_range` proves that their exhaustive union covers every vertex.
`Packet.check_iff`, `toCertificate_valid` and `toCertificate_check` bind those
proofs to the typed certificate, with target bounds proved before constructing
`Fin` targets. The existing weighted-maximum soundness theorem then applies
to any nonnegative measured masses satisfying the actual occurrence recurrence.
All computational proofs use `decide +kernel`; native evaluation is not used
as a proof oracle.

The generated module is first compiled to a fresh `.olean`. A separate importer
then audits every logical declaration exported by that specific module, including
helpers and data definitions, permitting only `propext`, `Classical.choice` and
`Quot.sound`. Importing uses Lean's exported transitive axiom cache; repeated
independent traversals before export were prohibitively expensive. The existing
isolated full-project gate separately audits the generic checker and all its
local dependencies.

The independent audit also checks that `accepted` and `typed_accepted` have
exactly the expected packet-check types. It emits `Packet.emit packet` directly,
without invoking the generated module's emitter. A valid Lean fixture with
misleading proof names (`accepted : True`) and an unrelated emitter is rejected.
A names-and-axioms-only audit could not establish this binding; this harness
weakness was found and corrected during implementation. The canonical source
generator and compiler remain explicit trust inputs; the API does not authenticate
an arbitrary caller-supplied executable as the canonical generator.

Lean finally decodes and emits the entire native packet, not a checksum of a
claimed result. The existing independent Python oracle reconstructs all 18
native graphs and compares each state, occurrence, weight and metadata field.
Its full receipt must equal the committed class receipt. This is runtime data
binding evidence, not a proved refinement of Mojo's compiler or graph engine.

## Negative controls

Lean controls refuse invalid target 3 in a three-vertex packet, zero weight,
missing rows, source index 18, incorrect binary-tree cuts, and nonzero hidden
payload beyond the declared row length. Six occurrences of the same target
refuse at rate 102/20, so multiplicity affects the inequality. A positive
terminal packet accepts. Mojo tests pin exact decimal serialization of an
empty row and a repeated-target row, and refusal of out-of-budget values.
Python tests calibrate only the audit protocol, including rejection of admissions,
native-reduction axioms, stale source IDs, duplicate declarations and missing
completion. Those synthetic logs are not mathematical evidence. The separately compiled
`tests/fixtures/c4_overlap_bad_binding.lean` is a real Lean calibration: its two
misleading proofs compile, but the independent type-binding audit refuses them.
The full and single-source gates require that refusal before replaying data.

Earlier monolithic kernel attempts exhausted the local 8 GiB budget, and bounded
forall over arrays had impractical kernel reduction cost. These are recorded as
incomplete attempts, not rejected mathematical certificates. The checked tree,
packed literals and bounded row proofs address those engineering limitations.

## Non-claims / remaining gaps

Even completed acceptance of all 285,786 vertices and 1,409,729 occurrences would
establish the concrete integer inequalities and data parity. It would not prove
occurrence-cover completeness from actual compact sets, M-adic/Haar scaling,
Hausdorff contraction of the actual prefix operator, or strict-cut positive
measure counting. The four period-three sources 12, 13, 15, 16 remain subject
to those same geometry bindings; the generic period-three inference is already
proved conditionally. No claim status, proof-ledger sufficiency edge, merge
state or human-review label changes.

## Prior art and decision

This implements the already reviewed finite checker interface in
[c4-overlap-lean-interface-2026-11-05.md](c4-overlap-lean-interface-2026-11-05.md).
It introduces no new proposed universal invariant. The existing literature
stop/go decision applies: proceed with this narrow data binding, preserve all
geometric hypotheses, and do not import a tiling/PDS equivalence. Kernel
performance choices follow the pinned Lean sources: `Array` has list semantics
in kernel reduction; `Nat.allLTTR_eq_true` justifies a Boolean bounded loop;
`Lean.Util.CollectAxioms` supplies imported axiom-cache inspection.
