# Audit — 2026-09-15: repository engineering state

**Scope.** Engineering audit of the tree at `be8b2c6` (main): verification
layers, CI, record consistency, hygiene, and supply chain. The mathematics is
audited only for *consistency across status surfaces*, not re-derived; see
`audit-2026-09-10.md` for the last mathematical audit.

**Method.** Ran every layer available in the audit container (provenance,
vendoring sync, pytest, ruff, mypy); read the CI job results for the head
commit for the layers that were not (Mojo, TLA+, Lean); cross-checked every
status surface against `tla/Ledger.tla` and the CI-enforced census numbers.

## 3. Findings

Ordered by severity.

### F1. No `LICENSE`, no `CITATION.cff` (high)

The tree contains a manuscript, proofs, and code but no license and no
citation metadata. Without a license nothing here is legally reusable, and
the vendoring relationship with NLAP-JT is undocumented at the license level.
Add a license (code and text may need different terms) and a `CITATION.cff`
pointing at the manuscript.

### F2. Unpinned toolchain fetches (medium)

| Fetch | Pinning | Risk |
|---|---|---|
| `curl -fsSL https://pixi.sh/install.sh \| bash` | none | installer drift |
| `tla2tools.jar` from `releases/latest` | none | TLC semantics/CLI change silently flips a HOLD/violation expectation |
| elan from `master` | none | installer drift |
| `modular >=26.6.0.dev2026090805,<27` on `max-nightly` | exact only via `pixi.lock` | any re-lock moves to a different nightly |
| Mathlib `inputRev = master` | `rev` pinned in manifest | fine as long as the manifest is committed with every bump |

The Mojo nightly dependency is the one that can invalidate exact certificates
without a source change. Prefer a stable `modular` release once one satisfies
the code, or at least document that `pixi.lock` is load-bearing. Pin the
TLA+ jar to a release tag and checksum it.

### F3. `docs/README.md` indexes 22 of 66 notes (medium)

44 notes are not mentioned in the index, including live ones:
`p1-overlap-minimal-obstruction-2026-09-14.md`,
`overlap-finiteness-and-coincidence-density-2026-09-13.md`,
`seed-patch-to-literature-overlap-audit-2026-09-13.md`, all `c4-*`, all
`p1b-*`, `automation-protocol.md`, `FINITE_SIGNING_PARITY.md`. The
superseded `completion-ledger-2026-09-11.md` is not marked superseded (the
09-11 architecture file is). Record drift was the main failure mode named in
the 2026-09-10 audit; an unindexed note is the first step of it. Either index
everything under a "supporting notes" heading or move retired notes into
`archive/`.

### F4. `verify_all.sh` hides pytest diagnostics (low)

`pytest -q >/dev/null 2>&1` reports FAIL with no output. Capture to a variable
and print on failure, as the Mojo and Lean sections already do.

### F5. No lint or type gate for the Python oracle (low)

`ruff` reports 78 findings (43 E702, 17 E701, 6 E401, 6 E731, 3 F401, 2 E741,
1 F841); `mypy` reports 11 errors in 6 files. All mypy errors are tuple-arity
annotations (`tuple[int]` vs `tuple[int, ...]`), none a runtime bug; the
`stack` reuse flagged in `overlap_obstruction.py` is two independent loops.
The unused imports/variable are genuine dead code. Add `ruff` and `mypy` to
the `python-tests` job with a `[tool.ruff]` block in `pyproject.toml`.

### F6. Duplicated 20-item test chains in `mojo/pixi.toml` (low)

`test` and `check` are the same `&&` chain of 20 `mojo run` commands with one
difference at the tail. A new test file must be appended to both by hand; a
miss is silent. Replace with a single shell loop over `tests/test_*.mojo` (or
`mojo test` once the project can use it).

### F7. Orphans (low)

- `src/psc_research/pip_screen.py`: no test imports it; 19 of the 78 ruff findings.
- `scripts/swap_overlap_depth_census.py`, `scripts/sweep_boundary_sync.py`: not referenced by any doc, workflow, or task.

Either cite them from the note they support or delete them.

### F8. Cross-repository paths written as bare relative paths (low)

`cross-program-bridge-psc-nlapjt-2026-09-12.md`,
`library-extraction-candidates-2026-09-14.md`, `mojo/finite_exact/UPSTREAM.md`,
and the vendored file headers refer to NLAP-JT files as `src/bigint_z.mojo`,
`docs/no-points-invariant.md`, `docs/project-audit-2026-09-14.md`, etc. None
of these paths exist in this tree. Qualify them (`NLAP-JT:src/...`) so a
link checker and a reader can tell them from local references.

### F9. Branch hygiene (low)

branch that PR #82 merged from. Delete merged branches and start each PR from
a fresh branch.

### F9 is blocked, not skipped

37 branches (not 32; the count grew) are fully merged into `main` and verified
as ancestors of it, with `main`, the working branch, and the three open pull
request heads excluded. Deleting them failed in this environment: the agent
proxy answers `git push --delete` with HTTP 403, and the GitHub MCP server
exposes no ref-deletion tool. Nothing was deleted, and no branch state changed.

The list is cheap to recompute, so it is not pinned here. From a checkout with
push rights:

```bash
git fetch --prune origin
git branch -r --merged origin/main | sed 's|^ *origin/||' \
  | grep -vE '^(main|HEAD)' > /tmp/merged.txt
# drop any open pull request head, then:
xargs -a /tmp/merged.txt git push origin --delete
```

A merged branch is recoverable: its commits are in `main`, and GitHub offers
Restore branch on the merged pull request.
