## 2024-10-18 - Preserve Order When Avoiding Generator Iteration
**Learning:** When trying to optimize divisor generation and polynomial root evaluation by removing `list` allocations and combining loops, do not interleave checks for a small divisor `d` and its large complement `q = value // d` in the same iteration if the function is specifically designed to check candidates in ascending order. Doing so regresses performance significantly for high-degree polynomials by evaluating large candidates before intermediate ones.
**Action:** When manually unrolling divisor logic, explicitly separate the process into two phases: a forward loop `for d in range(1, limit + 1)` and a backward loop `for d in range(limit, 0, -1)` checking the complement `q = value // d`. This keeps the list allocation out while preserving the required ascending check order.
